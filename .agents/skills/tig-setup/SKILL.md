# TIG setup for product generation

Every product in this repository is generated by a `demo-*.sh` script that runs
VICAR/MARS programs inside a container through the `tig` CLI. Do this once per
host before using any of the `tig-generate-*` skills.

## 1. tig CLI and container runtime

```bash
docker info >/dev/null          # Docker (or Podman via TIG_CONTAINER_RUNTIME) must be running
pip install tig-cli             # or: pip install -e ./tig-cli from this repo
tig --help | sed -n '1,12p'     # prints the active image and calibration path
```

The first `tig` call pulls `ghcr.io/nasa-ammos/tig/terrain-intelligence-generator:opensource`
(~3 GB) and starts a long-lived container that is reused by every later call.
`tig --status` shows it; `tig --shutdown` removes it (do this after changing
`CONTAINER_IMAGE` or `MARS_CONFIG_PATH`, otherwise the old container keeps the
old settings).

## 2. Calibration

MARS programs need the mission's camera models even when they only read an XYZ
label. A calibration directory must directly contain `camera_models/` and
`param_files/`.

Preferred: download from the open-source VICAR 5.0 release (no account needed):

```bash
./fetch-calibration.sh --list      # missions and sizes (~5 s)
./fetch-calibration.sh -y msl      # 380 MB -> ~/.mars_calib/msl
./fetch-calibration.sh -y m20      # 2.7 GB download, 5.3 GB installed - only if you need M20
export MARS_CONFIG_PATH=~/.mars_calib/msl
```

Pick the mission that produced your input frames: `msl` for `N[LR]B_*` MSL
NavCam, `m20` for `N[LR]F_*` / `Z[LR]F_*` Mars 2020 frames, `nsyt` (117 MB) is
the smallest for smoke tests. The demo scripts resolve calibration via
`find-calibration.sh` (`$MARS_CONFIG_PATH`, `$MARS_CALIB_PATH`, `./calibration`,
`~/.mars_calib[/<mission>]`, `/opt/mars_calib`) and, when nothing is found,
offer the download themselves; `TIG_FETCH_CALIBRATION=1` accepts without a
prompt (needed in non-interactive shells).

Alternative with nothing to download: a `:visor-<mission>` image bundles one
mission's calibration:

```bash
export CONTAINER_IMAGE=ghcr.io/nasa-ammos/tig/terrain-intelligence-generator:visor-msl
tig --shutdown
```

A host `MARS_CONFIG_PATH` mount always overrides bundled calibration.

Verify before spending minutes on a pipeline:

```bash
ls "$MARS_CONFIG_PATH"/camera_models "$MARS_CONFIG_PATH"/param_files | head
tig bash -c 'echo $MARS_CONFIG_PATH; ls $MARS_CONFIG_PATH | head'
```

## 3. Input data

| Need | Source |
| --- | --- |
| MSL NavCam frames, stereo pair, XYZ (~740 MB) | `visor_sample_data_20230623.tar.gz` from https://github.com/NASA-AMMOS/VICAR/releases/tag/5.0 |
| Mars 2020 NavCam EDR/RAD frames | PDS Imaging Node, e.g. `https://pds-imaging.jpl.nasa.gov/data/mars2020/mars2020_navcam_ops_raw/data/sol/00650/ids/edr/ncam/` |

```bash
mkdir -p ~/visor_data
curl -sL https://github.com/NASA-AMMOS/VICAR/releases/download/5.0/visor_sample_data_20230623.tar.gz \
  | tar -zxf - -C ~/visor_data
```

Useful sample files (all MSL, site/drive `F0961766`, calibration `msl`):

- `sample_data/StereoCorrelation/N{L,R}B_712299404EDR_F0961766NCAM00353M1.IMG` - stereo pair
- `sample_data/OrthorectifiedMosaic/NLB_712299404XYZ_F0961766NCAM00353M1.IMG` - XYZ cloud
- `sample_data/CylindricalMosaic/NLB_*ILT*.IMG` - 19 left NavCam frames for mosaics / co-registration

There are no M20 frames in the sample tarball. Always check a download is a
real product and not an HTML landing page: `head -c 200 file.IMG`.

## 4. Path and workspace conventions

- `tig` mounts `$PWD` and `$HOME` read-write and translates paths given as
  **command arguments**. It does not rewrite paths inside list files (`.lis`,
  `.txt`). Put container-visible paths in list files: the original absolute
  path for anything under `$HOME`, `/host<abs-path>` for anything else, and
  resolve symlinks first (`readlink -f`). Add `--writable-path DIR` to write
  outside `$PWD`/`$HOME`.
- Run the demo scripts from the repository root. They write into `workspace/`
  (mesh, panorama, surface characteristics), `workspace-coreg/`
  (co-registration) or `workspace-change/` (change monitoring, overridable
  with `--workspace`). Use a fresh or emptied workspace per
  product: leftover files from an earlier run make a failed stage look
  successful. The mesh script removes its own previous outputs
  (`terrain.*`, `texture.*`, `disparity*.img`, `pointcloud*.xyz`) from
  `workspace/` before it starts, so copy products you want to keep first.
- VICAR programs write `.img`/`.vic` files; convert for viewing with
  `tig vicario in.img out.png` (16-bit HALF data usually needs a `stretch` or
  `cform` first - each product skill says which).
- Inspect any product with `tig label -list file.img` (dimensions, format,
  bands, camera model, coordinate frame).

## 5. Known runtime issues

- **Exit 136 from `marsmap`, `marsremos`, `marscor2`, `marsint`** on older
  images: an MPI/hwloc crash. Run with `tig env HWLOC_COMPONENTS=-x86 marsmap ...`.
  Current images set this internally, so try the plain command first.
- **`marsirough` abends** (`Exception in XVREAD ... zix`) on every input: an
  upstream VICAR bug; the surface-characteristics demo treats it as optional.
- **Empty or all-black PNG**: the VICAR product is fine, the conversion was
  not stretched. See the product skill for the right `stretch`/`cform` call.
- **`Calibration ... not found`**: `MARS_CONFIG_PATH` points at a wrapper
  directory. It must contain `camera_models/` directly (e.g. `~/.mars_calib/msl`,
  not `~/.mars_calib`).

## Product skills

`tig-demo-testing` skill.
